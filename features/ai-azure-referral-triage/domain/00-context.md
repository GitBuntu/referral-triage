## Purpose
**Context Name**: ai-azure-referral-triage

**Responsibility**: This bounded context enforces that referral documents submitted for intake must be triaged and classified before downstream clinical workflows can access the result. State it as an invariant: "Referrals must be classified with specialty and urgency before triage is complete."

**Boundaries**: This context is bounded by:
- **Upstream inputs**: None.
- **Downstream outputs**: Clinical-workflow-service receives Referral-Triaged event when referral intake and triage are complete. Clinical-workflow-service responds by initiating appropriate specialty workflow.
- **Not included**:
  - Clinical workflow execution (owned by clinical-workflow-service)
  - Patient record management (owned by patient-management-service)
  - Authorization and permissions (owned by auth-service)

## Ubiquitous Language
Each term MUST follow this exact format.

- **Referral**:
  - Meaning: A request for medical evaluation submitted for a specific patient, containing a medical document and associated metadata.
  - Used in: Referral aggregate, ReferralDocument value object, Referral-Submitted event, Referral-Triaged event

  - Example usage: "Referral {id: REF-001, status: pending} is submitted and awaits triage"

- **Document**:
  - Meaning: The physical or digital artifact representing the referral (PDF, text, scanned image) containing clinical information.
  - Used in: ReferralDocument value object
  - Not to be confused with: Referral (which includes metadata beyond the document)
  - Example usage: "ReferralDocument {format: pdf, size: 245KB, content: binary} is stored in Blob Storage"

- **Triage**:
  - Meaning: The process of analyzing a referral document through AI to classify specialty, assess urgency, and extract key clinical fields.
  - Used in: Referral aggregate, TriageProcessor domain service, Referral-Triaged event
  - Not to be confused with: Clinical diagnosis (owned by clinical domain)
  - Example usage: "Referral triage completes when TriageRecord is generated with specialty=cardiology, urgency=urgent"

- **Specialty**:
  - Meaning: The medical discipline or department to which the referral should be routed (e.g., cardiology, orthopaedics, neurology, dermatology, general medicine).
  - Used in: TriageResult value object, TriageRecord aggregate
  - Not to be confused with: Department (organizational structure)
  - Example usage: "TriageResult.Specialty == cardiology indicates the referral belongs to cardiovascular medicine"

- **Urgency**:
  - Meaning: The priority level assigned to a referral indicating how quickly it should be processed (routine, soon, urgent).
  - Used in: TriageResult value object, TriageRecord aggregate
  - Not to be confused with: Clinical severity (assessed by clinicians, not AI)
  - Example usage: "TriageResult.Urgency == urgent means referral is processed within 24 hours"

- **Invariant**:
  - Meaning: A constraint that must always hold true to maintain domain consistency.
  - Used in: Invariants section, test assertions
  - Not to be confused with: Business rule (may be context-dependent)
  - Example usage: "Referral-UrgencyInvariant states that Urgency must be one of {routine, soon, urgent}"

- **ReferralId**:
  - Meaning: A unique identifier assigned to a referral at submission time, used to track and retrieve the referral throughout its lifecycle.
  - Used in: Referral aggregate root, ReferralIdentity value object, Referral-Submitted event payload
  - Not to be confused with: DocumentId (identifier for the stored document), PatientId (identifier in patient-management-service)
  - Example usage: "ReferralId == uuid-1234-5678 uniquely identifies this referral within ai-azure-referral-triage context"

- **TriageRecord**:
  - Meaning: The structured output of AI-based triage containing classification results, extracted fields, and a clinical summary for a referral.
  - Used in: TriageRecord aggregate, Referral-Triaged event
  - Not to be confused with: Referral (the input), Clinical record (created downstream)
  - Example usage: "TriageRecord {specialty: cardiology, urgency: urgent, summary: chest pain investigation} is the result of processing a referral"

- **ClincalSummary**:
  - Meaning: A brief natural-language summary of the referral content generated by AI, highlighting key clinical information.
  - Used in: TriageResult value object, TriageRecord aggregate

## Value Objects

- **ReferralIdentity**:
  - Immutable attributes: ReferralId: UUID, CreatedAt: timestamp
  - Input validation rules: ReferralId must be non-null UUID, CreatedAt must be current timestamp at creation
  - Equality: Equality by value, not by reference
  - Owned by: Referral

- **ReferralDocument**:
  - Immutable attributes: Format: string (pdf, text, image), Size: integer (bytes), StoragePath: string, Hash: string
  - Input validation rules: Format must be in {pdf, text, image}, Size > 0 and < 50MB, StoragePath must be non-empty, Hash must be valid SHA-256
  - Equality: Equality by value, not by reference
  - Owned by: Referral

- **TriageResult**:
  - Immutable attributes: Specialty: string, Urgency: string, ExtractedFields: map<string, string>, ClinicalSummary: string
  - Input validation rules: Specialty must be in {cardiology, orthopaedics, neurology, dermatology, general_medicine}, Urgency must be in {routine, soon, urgent}, ExtractedFields must contain {patient_name, dob, symptoms, duration, red_flags}, ClinicalSummary must be non-empty and < 500 characters
  - Equality: Equality by value, not by reference
  - Owned by: TriageRecord

## Invariants

- **Referral-UniqueIdInvariant**:
  - Measurable form: Each Referral.ReferralId must be globally unique (no two Referral aggregates share the same ReferralId)
  - Example violation: Two Referral aggregates both have ReferralId == uuid-1234. System retrieves both; caller cannot distinguish referrals.
  - Impact: Referral tracking fails; downstream systems cannot determine which referral is being processed
  - Enforced by: Referral aggregate constructor validates and generates unique ReferralId; Repository enforces unique constraint on storage

- **Referral-DocumentRequiredInvariant**:
  - Measurable form: Referral.Document != null (every referral must have an associated document)
  - Example violation: Referral created without document. System attempts to triage null document; triage processor crashes.
  - Impact: Triage processing fails; referral cannot be classified; workflow blocked
  - Enforced by: Referral.InitiateIntake() method requires ReferralDocument parameter; constructor rejects null

- **TriageRecord-SpecialtyInvariant**:
  - Measurable form: TriageRecord.TriageResult.Specialty in {cardiology, orthopaedics, neurology, dermatology, general_medicine}
  - Example violation: TriageResult.Specialty == "unknown". Workflow router cannot match specialty to department.
  - Impact: Referral cannot be routed to correct specialty; clinical workflow fails
  - Enforced by: TriageResult value object constructor validates Specialty against allowed set

- **TriageRecord-UrgencyInvariant**:
  - Measurable form: TriageRecord.TriageResult.Urgency in {routine, soon, urgent}
  - Example violation: TriageResult.Urgency == "critical". SLA checker expects only 3 levels; downstream system crashes.
  - Impact: SLA processing fails; triage record rendered invalid
  - Enforced by: TriageResult value object constructor validates Urgency against allowed set

- **TriageRecord-KeyFieldsInvariant**:
  - Measurable form: TriageRecord.TriageResult.ExtractedFields contains keys {patient_name, dob, symptoms, duration, red_flags} with non-empty values
  - Example violation: ExtractedFields missing red_flags key. Clinical workflow attempts field lookup; crashes with null reference.
  - Impact: Downstream clinical systems cannot access critical red flags; patient safety compromised
  - Enforced by: TriageResult value object constructor validates all required fields present and non-empty

- **TriageRecord-ClinicalSummaryInvariant**:
  - Measurable form: TriageRecord.TriageResult.ClinicalSummary != empty AND length < 500
  - Example violation: ClinicalSummary is empty. Clinical staff cannot understand referral summary; must re-read original document.
  - Impact: Reduces efficiency gains of AI triage; clinical staff workload increases
  - Enforced by: TriageResult value object constructor validates ClinicalSummary length

## Repositories

- **Referral**:
  - Interface: IReferralRepository
  - Load patterns: by ReferralId, by status (pending, triaged, failed), by date range (CreatedAt), by submission_source
  - Save lifecycle: on creation [when Referral-Submitted event is emitted] — aggregate becomes retrievable by ReferralId and date range; on state change [when Referral-Triaged event is emitted] — aggregate becomes retrievable by status (pending → triaged)

- **TriageRecord**:
  - Interface: ITriageRecordRepository
  - Load patterns: by ReferralId, by specialty, by urgency, by date range (CreatedAt)
  - Save lifecycle: on creation [when Referral-Triaged event is emitted] — aggregate becomes retrievable by ReferralId, specialty, and urgency

## Domain Events

- **Referral-Submitted** (Naming pattern: Referral-Submitted):
  - Emitted by: Referral aggregate
  - Trigger: when Referral.InitiateIntake() is called AND ReferralDocument is valid AND ReferralId is generated
  - Payload: ReferralId: UUID, DocumentFormat: string, DocumentHash: string, SubmittedAt: timestamp, SubmittedBy: string
  - Invariants preserved: Referral-UniqueIdInvariant, Referral-DocumentRequiredInvariant
  - Save lifecycle triggered: Referral repository saves on creation
  - Consequence: AI-triage-processor context receives Referral-Submitted and triggers OCR+AI triage; external logging-service receives event for audit trail

- **Referral-Triaged** (Naming pattern: Referral-Triaged):
  - Emitted by: TriageRecord aggregate
  - Trigger: when TriageRecord.CompleteTriageFromAIResult() is called AND TriageResult contains valid specialty, urgency, and all required fields
  - Payload: ReferralId: UUID, Specialty: string, Urgency: string, ExtractedFields: map, ClinicalSummary: string, TriagedAt: timestamp
  - Invariants preserved: TriageRecord-SpecialtyInvariant, TriageRecord-UrgencyInvariant, TriageRecord-KeyFieldsInvariant, TriageRecord-ClinicalSummaryInvariant
  - Save lifecycle triggered: TriageRecord repository saves on creation; Referral repository updates status to triaged
  - Consequence: clinical-workflow-service receives Referral-Triaged and initiates workflow for appropriate specialty; metrics-aggregation-service receives event for daily aggregation
