## EARS Requirement Pattern
**State driven:** While the calendar date advances to the next day (timer trigger at 02:00 UTC), the DailyMetrics aggregate shall invoke the MetricsCalculator domain service to query all Referral aggregates processed in the previous day, aggregate counts by specialty, count urgency distribution (routine, soon, urgent), calculate average processing latency, calculate missing-field rate, create a Metrics value object, emit MetricsAggregated event, and store the metrics in Table Storage at /metrics/daily.

---

## Requirement Statement
While the scheduled timer trigger executes at 02:00 UTC each day, the DailyMetrics aggregate shall invoke the MetricsCalculator domain service to query the IReferralRepository for all Referral aggregates with TriageRecord.ClassificationTimestamp within the previous calendar day (00:00-23:59 UTC), aggregate the count of processed referrals by medical specialty (cardiology, orthopedics, neurology, dermatology, general medicine), count the distribution by urgency level (routine, soon, urgent), calculate the average processing latency in milliseconds across all processed referrals, calculate the missing-field rate as a ratio of referrals with any empty required field to total processed referrals, create a Metrics value object with MetricsDate set to the previous calendar day and all calculated values, emit MetricsAggregated domain event with complete payload including metrics date, per-specialty counts, urgency counts, average latency, processed count, missing-field rate, and aggregation timestamp, and persist the DailyMetrics aggregate to Table Storage.
